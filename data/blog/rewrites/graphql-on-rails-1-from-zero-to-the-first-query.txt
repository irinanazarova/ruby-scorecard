GraphQL is a query language and runtime for APIs, and this multi-part tutorial explains how to build a GraphQL application using Ruby on Rails on the backend and React with Apollo on the frontend, starting from an empty project and working all the way up to your first working query. Rather than rushing you into a rewrite, it teaches both the basics and the more advanced topics by example, so that by the end you understand not only what makes the technology powerful but also where its sharp edges lie.

GraphQL has become one of those new and shiny things that show up everywhere you look, from blog posts and conferences to podcasts and beyond, and the constant buzz can make it feel as though you should hurry to replace every REST endpoint in your application immediately. The honest answer is that you probably should not, because there is no silver bullet, and it is worth understanding the genuine pros and cons of any technology before committing to a paradigm-shifting decision. This series therefore offers a no-frills guide to developing GraphQL applications, discussing its real advantages alongside the caveats and pitfalls you are likely to encounter.

To see why GraphQL behaves the way it does, it helps to start with its specification, which describes GraphQL as both a query language and a runtime, sometimes called an execution engine. The query language describes how a client communicates with an information system, while the runtime is responsible for actually fulfilling those queries with data. At the core of every GraphQL application lies a schema that describes the underlying data as a directed graph, and the runtime must execute every query according to that schema and the general rules laid out in the specification. Because of this, every valid GraphQL server runs queries in the same way and returns data in the same format for a given schema, which means the schema is effectively everything a client needs to know about the API.

A single query represents a sub-graph of the schema, which delivers the first major benefit of GraphQL, since clients can fetch exactly the data they need, all at once, in one request. That property neatly solves overfetching, a common problem with traditional REST APIs, and because GraphQL schemas are strongly typed, both the client and the runtime can ensure that the data passed back and forth is always valid.
