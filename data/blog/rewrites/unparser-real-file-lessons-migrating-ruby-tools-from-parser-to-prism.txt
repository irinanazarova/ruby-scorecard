Prism is the new built-in Ruby parser that ships with Ruby 3.4, and this article explains what it takes to move existing Ruby tooling from the older Parser gem onto it, using the Unparser project as a worked example. A parser is the component that reads Ruby source code and turns it into a structured representation that other programs can analyze, and Prism is designed to be faster, more portable, and a stable foundation for the next generations of Ruby tools. Because every tool that works with Ruby's syntax depends on a parser, this shift reaches across the whole ecosystem, affecting linters, formatters, IDEs, static analyzers, and many other tools that need to understand code rather than merely run it.

The encouraging conclusion of our experience is that the transition from Parser to Prism is genuinely doable, but it is far from automatic, because along the way you have to navigate differences in the two libraries' APIs, adjust to the new shapes that Prism gives to the abstract syntax tree, account for a surprising amount of edge-case syntax, and test the result thoroughly before you can trust it. To understand why this work is harder than it first appears, it helps to start by appreciating just how difficult a job any Ruby parser actually has.

Ruby's syntax is extremely expressive and friendly to developers, and that expressiveness comes at a real cost, because the infrastructure that has to handle every legal construction, most notably the parsing system, becomes genuinely challenging to build and maintain. The examples that follow are all perfectly valid Ruby rather than typos or deliberate code golf, yet they push hard against the edges of the language's grammar. We can construct ranges with the usual two-dot and three-dot syntax, but Ruby will also happily parse an expression with five dots in a row and interpret it as a range whose bounds are themselves ranges. The flip-flop operator is already rare, yet Ruby accepts incomplete flip-flops that omit either their left or right operand, and these are so uncommon that some tools fail when they first encounter one. When you rescue an exception, the assignment target can be far more than a simple local variable, extending to constants, method calls, and even indexed assignments, which forced us to patch Prism's Parser translation layer so that this unusual syntax would survive the migration intact.
