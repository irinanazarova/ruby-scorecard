Freezolite is a Ruby gem that automatically freezes string literals across an entire project without requiring you to add the magic comment to every file by hand. This guide explains the performance problem that frozen string literals solve, why Ruby allocates a fresh object for every literal string, and how Freezolite lets you opt your whole codebase into frozen literals safely. The gem was built by the team at Evil Martians after a recurring frustration surfaced: developers wanted a way to set frozen_string_literal to true for a whole project so they could stop adding the comment file by file and stop fighting the RuboCop warnings that flag every file missing it.

To understand why this matters, it helps to know how Ruby treats strings. In Ruby, almost everything is mutable by default, and that includes strings. This design fits the language's dynamic nature well, but it can introduce noticeable downsides at scale, primarily around performance. Because a string can be modified in place, Ruby cannot safely reuse the same object in multiple places, so it copies the string each time to avoid race conditions, and that is exactly what it does with literal strings written directly into your source code.

A literal string is one defined in the source code itself, created statically rather than constructed dynamically at runtime. Consider a simple class whose only method returns the literal string "meow". Even though that string is identical for every instance you create, Ruby allocates a brand new String object every single time the method runs, and the same is true when you call the method repeatedly on one object. You can confirm this by counting allocations with ObjectSpace before and after invoking the method many times in a loop, and you will see that each call produces another string. Marking the literal with .freeze removes those repeated allocations because the frozen object can be reused safely.

Now imagine generating thousands of such strings within a single unit of work, for example while processing one web request. That volume of throwaway objects places real stress on Ruby's garbage collector and can degrade response times for no good reason, a pattern that often appears in the presentation layer of Rails applications. Recognizing this, the Ruby Core team introduced the frozen_string_literal magic comment in Ruby 2.3 so that a single line at the top of a file freezes every literal in it.
