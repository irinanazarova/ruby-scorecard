In this lesson you will learn how a complete Ruby on Rails web application, including both its user-facing pages and its server-side logic, can be made to run entirely inside a web browser through a technology called WebAssembly. By the end, you should understand what WebAssembly is and why it matters, what makes Ruby on Rails distinctive among web frameworks, what the term full-stack means, and how the browser itself can serve as a runtime that executes a program rather than merely displaying documents. Each of these ideas builds on the one before it, so we will define each term carefully the first time it appears and then explain why that concept changes what is possible on the modern web.

WebAssembly, often abbreviated as Wasm, is a low-level binary instruction format that allows code written in languages other than JavaScript to run inside a web browser at speeds approaching those of native applications. WebAssembly matters because it was originally designed to bring high-performance and securely sandboxed features to the web, yet it has since grown into a portable runtime that also powers cloud computing and embedded systems, which means a single compiled program can run in many different environments. Ruby on Rails is a web application framework, written in the Ruby programming language, that emphasizes developer productivity and the ability to ship working software quickly, and it is the foundation behind well-known platforms such as GitHub and Shopify. Understanding Rails matters here because it represents the kind of full-featured server-side framework that was traditionally assumed to require a dedicated server, an assumption this lesson will directly challenge.

The phrase full-stack refers to an application that includes both the frontend, meaning the visual interface a person interacts with, and the backend, meaning the server-side code that stores data and enforces the application's rules. Normally these two halves live in separate places connected over a network, but when the browser acts as a runtime, an environment that loads and executes program code rather than only rendering pages, that network distance can disappear entirely. This idea matters because it allows a server-side framework like Rails to run locally with no servers and no cloud services involved, which fundamentally blurs the boundary between client and server. To make these abstractions concrete, we will recreate the famous demonstration in which Rails builds a working blog in fifteen minutes, and then we will package that same application so it runs directly in your browser.
