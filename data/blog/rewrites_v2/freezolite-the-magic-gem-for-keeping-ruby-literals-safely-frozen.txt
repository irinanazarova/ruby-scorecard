In this article you will learn how Ruby handles the text values written directly into your source code, why those values can quietly slow a program down, and how a small library called Freezolite lets you fix the problem across an entire project at once. To follow the explanation, you will first need to understand what a string literal is, what it means to freeze a value in Ruby, how the special frozen_string_literal magic comment works, and how the related ideas of memory allocation and garbage collection shape a program's performance, so each of these terms is defined carefully as it appears.

A string literal is a piece of text written directly in the source code, such as the word "meow" typed between quotation marks, which means it is created statically as part of the program rather than being built up dynamically while the program runs. In Ruby almost every value is mutable by default, including strings, which means the contents of a string can be changed after it has been created, and this flexible design suits Ruby's dynamic character but carries a hidden cost at scale. Because a mutable string could be altered by any part of the program, Ruby cannot safely share a single copy of a literal everywhere it is used, so every time the program reaches that literal it allocates a brand new String object in memory, even when the text is identical each time.

Memory allocation is the act of reserving space in memory to hold a newly created object, and garbage collection is the automatic process by which Ruby later reclaims the memory of objects that are no longer needed, so creating thousands of identical throwaway strings forces the garbage collector to work harder and can noticeably degrade performance, especially in code that generates a great deal of text such as serializers and presenters. Freezing a string means marking it as immutable, that is, permanently unchangeable, which is important because an immutable value can be reused safely without copying, eliminating those redundant allocations. To make freezing easier, Ruby 2.3 introduced the frozen_string_literal magic comment, a special line that automatically freezes every string literal in a single file, and Freezolite is a gem, a packaged Ruby library, that extends this behavior across a whole project so you no longer need to add that comment to each file by hand.
