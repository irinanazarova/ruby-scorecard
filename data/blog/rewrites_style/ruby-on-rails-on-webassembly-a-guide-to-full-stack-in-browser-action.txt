Imagine a fully functional blog running in your browser, not just the frontend, but the backend too, with no server and no cloud anywhere in the picture.

WebAssembly, or Wasm, is a portable binary instruction format that lets code written in languages other than JavaScript run inside the browser at near-native speed, and it was originally introduced to bring high-performance and secure features to the web. That same runtime now reaches well beyond the page, because Wasm has become one of the building blocks for cloud computing and embedded systems, and the browser is only one of several places it executes. Ruby on Rails is a server-side web framework focused on developer productivity and shipping software fast, and it is the technology behind industry leaders such as GitHub and Shopify. A full-stack application normally splits into two halves that talk over a network: a frontend rendered in the browser, and a backend that runs the framework, the database, and the business logic on a remote machine. The interesting move this post explores is collapsing that split entirely, because once you compile Ruby itself to WebAssembly you can embed a typical server-side Rails application directly into the browser, which erases the distance between the frontend and the backend of an ordinary web application.

This guide shows how to take Rails into the browser in about fifteen minutes, a deliberate nod to the famous "How to build a blog in 15 minutes" video that David Heinemeier Hansson published in 2005, when building a working web application that fast still felt like magic. The plan is concrete: we create a normal Rails application and scaffold a blog the usual way on the command line, then package that same application for Wasm so it boots and runs as a self-contained unit inside the browser, with the request cycle, the models, and the views all executing locally. Repurposing a runtime far beyond its intended design is a recurring pattern in software, and running a backend framework with no backend is a sharp example of it. Along the way we cover the mechanics of making Rails Wasm-ready, what wasmification actually involves under the hood, and where Rails and WebAssembly are heading next.
