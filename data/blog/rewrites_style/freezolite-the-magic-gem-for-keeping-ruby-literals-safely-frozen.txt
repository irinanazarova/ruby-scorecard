Every Ruby program quietly allocates more memory than it needs to, and the plain text values you typed into your own source code are a bigger part of that waste than most developers expect. This article explains how Ruby handles those text values, why they slow a program down without anyone noticing, and how a small library called Freezolite removes the problem across an entire project at once. To follow the reasoning you first need to understand what a string literal is, what it means to freeze a value in Ruby, how the frozen_string_literal magic comment works, and how memory allocation and garbage collection shape performance, so each term is defined as it appears.

A string literal is a piece of text written directly into the source code, such as the word "meow" typed between quotation marks and returned by a method, which means it is created statically as part of the program rather than being constructed dynamically while the program runs. In Ruby almost every value is mutable by default, including strings, which means the contents of a string can be changed in place after it has been created, and this flexible design suits the language's dynamic character but carries a hidden cost at scale. Because a mutable string could be altered by any part of the program, Ruby cannot safely share one copy of a literal everywhere it appears, so each time execution reaches that literal it allocates a brand new String object even when the text is identical on every call.

The waste is easy to see once you count it: a method that returns an ordinary literal one hundred times allocates one hundred separate String objects, while the same method returning a frozen literal allocates none, because the single immutable object is built once and then handed out repeatedly. Memory allocation is the act of reserving space to hold a newly created object, and garbage collection is the automatic process by which Ruby later reclaims the memory of objects no longer in use, so generating thousands of identical throwaway strings forces the garbage collector to work harder, particularly in serializers, presenters, and decorators that produce a great deal of text on a single web request. Freezing a string means marking it as immutable and permanently unchangeable, which matters because an immutable value can be reused safely without copying, eliminating those redundant allocations. Ruby 2.3 introduced the frozen_string_literal magic comment, a line that automatically freezes every string literal in the file where it appears, and Freezolite is a gem, a packaged Ruby library, that extends this behavior across a whole project so you never repeat that comment by hand.
