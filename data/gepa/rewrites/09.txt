This article explains how to set up a Docker-based development environment for Ruby and Ruby on Rails projects, an approach the author and his colleagues call "Ruby on Whales." Ruby on Rails is a popular web application framework written in the Ruby programming language, and like most software projects, a Rails application depends on many supporting pieces: a specific version of the language itself, a database such as PostgreSQL, a JavaScript runtime such as Node.js, and various system libraries. Getting all of these installed correctly on each developer's machine is often tedious and error-prone, and small differences between machines lead to the familiar complaint that code "works on my machine" yet fails elsewhere.

The central idea here is the reproducible development environment, meaning a setup that behaves identically for every person working on a project, regardless of the operating system or tools already installed on their computer. A reproducible environment makes it far easier to bring new engineers onto a team, to let non-engineers spin up a project, and to roll out changes to shared infrastructure such as databases and native dependencies without each person having to reconfigure their own machine by hand.

The common way to achieve this today is containerization. A container is a lightweight, isolated package that bundles an application together with everything it needs to run, so the same dependencies are present everywhere the container is launched. Containers can run on a developer's own laptop through tools like Docker or Podman, or remotely through services such as Codespaces, Coder, and Gitpod. A project's dependencies can be placed in a single container, or split across several containers in a multi-service architecture where the application, the database, and other services each run separately and communicate with one another.

Ruby on Whales applies these ideas specifically to Ruby on Rails. It is a local development configuration built around Docker, using a multi-service architecture managed through Docker Compose, the tool that coordinates several containers as one system. The author arrived at this configuration over several years, beginning with heavier virtual machines before moving to containers in 2017, and the sections that follow explain how the setup works and the reasoning behind its choices.
