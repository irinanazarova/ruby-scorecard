This guide explains how to connect a browser or other client application to AnyCable from the client side, using the AnyCable JavaScript SDK to open a real-time connection, subscribe to data streams, and exchange messages with your server. AnyCable is a real-time server that speaks the Action Cable protocol, the same protocol that powers real-time features in Ruby on Rails applications, so that your backend can push live updates to connected clients over a persistent connection rather than relying on repeated polling. That persistent connection is a WebSocket, a long-lived, two-way channel between the browser and the server that stays open so either side can send data at any time. A client SDK is the library you load into your front-end application to manage that connection for you, handling the details of opening the socket, subscribing to channels, sending actions, and receiving messages, so you can work with a small, well-defined set of methods instead of raw protocol frames.

Because AnyCable's server implements the Action Cable protocol, you can in principle reach it with any existing Action Cable client library, including the official @rails/actioncable package. Even so, the AnyCable team recommends its own JavaScript SDK for several practical reasons that go beyond basic compatibility. The SDK works across multiple platforms out of the box, supporting web pages, web workers, React Native, and Node.js from a single codebase, and it ships with TypeScript support so that connections, channels, and messages can be typed and checked as you write them. It also extends the underlying protocol with capabilities the standard client lacks, such as binary message formats and AnyCable-specific features like reliable streams and signed streams, and it offers improved integration with Turbo Streams for developers building Hotwire-style interfaces.

The SDK is distributed as an npm package, and you can add it to a project with whichever package manager you already use, whether that is npm, Yarn, or pnpm. For browser applications you install the @anycable/web package, which assumes a web environment and wires up sensible defaults for it. If instead you are running in a non-web environment such as a Node.js service or a background worker, you should install the @anycable/core package, which provides the same underlying client without the browser-specific assumptions. Once the package is installed, the following sections walk through creating a connection, subscribing to streams, and defining channels in your application.
