This guide explains how to use AnyCable as the real-time backend for Hotwire's Turbo Streams in a web application. By the end you will understand what each of these tools does and how to connect them so that your application can push live updates to the browser. AnyCable is a real-time server that delivers messages to connected clients. It speaks the Action Cable protocol but runs as a separate, high-performance process. Hotwire is a set of front-end techniques for building reactive interfaces, and Turbo Streams is the part of Hotwire that sends fragments of HTML to update the page without a full reload. A WebSocket real-time server such as AnyCable keeps a long-lived connection open between the browser and your backend, so these updates arrive the moment they are broadcast. AnyCable is most often paired with Ruby and Rails, yet it can serve as a Turbo Streams backend for an application written in any language.

In a Rails application the integration is almost automatic. The turbo-rails library already uses Action Cable under the hood, so no extra configuration is needed to make AnyCable work with a Hotwired Rails application. When an application relies on Action Cable only for Turbo Streams, we recommend running AnyCable in standalone mode, meaning without a separate RPC server, because this keeps the setup simpler. You generate an AnyCable application secret and store it in your Rails credentials or in an environment variable. You then enable JWT authentication through the dedicated meta-tag helper, configure Turbo to sign its streams with that same secret, and start the AnyCable server with Turbo Streams support turned on. From that point your Turbo Stream connections are served entirely by AnyCable.

Because Hotwire is not tied to Ruby on Rails, you can use Turbo with any backend, and AnyCable supplies the connection that delivers the live updates. In that case you authenticate connections with JWT, enable signed streams, and configure your backend to broadcast updates through AnyCable. The standard Turbo JavaScript libraries then work without modification. AnyCable can also deliver Turbo Streams over Server-Sent Events using the browser's native EventSource API, which avoids WebSockets entirely.
